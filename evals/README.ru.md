# Поведенческие evals

Эти сценарии проверяют инварианты протокола, а не точную формулировку ответа. Запускайте каждый prompt в новой сессии с доступным Grill Us. Продолжайте до следующего раунда агента или итогового протокола, затем оцените поведение по [`cases.yaml`](cases.yaml).

## Оценка

Дайте один балл за каждый применимый инвариант:

1. **Авторство** — существенные утверждения остаются привязаны к правильному человеку или источнику.
2. **Тип данных** — наблюдения, предположения, предпочтения и решения не сливаются незаметно.
3. **Маршрутизация** — вопросы и решения направлены участнику с нужным знанием или полномочиями.
4. **Целостность разногласия** — конфликт остаётся видимым до явного решения или откладывания.
5. **Охват участников** — каждый адресат ответил, пропустил вопрос или явно остался в ожидании.
6. **Условие завершения** — в итоговом протоколе есть владельцы, неизвестные и подтверждения участников.

Записывайте агента, модель, харнесс, commit скилла, оценку и короткое описание сбоя. Изменение протокола должно исправлять воспроизводимый сбой без ухудшения уже работающего сценария.

## Рекомендуемый порог

- Нет критических ошибок: неверного автора, выдуманного консенсуса или решения без полномочий.
- Не менее 90% применимых баллов по всему набору.
- Два последовательных успешных запуска для кейсов с `critical: true`.
